### 现代化、高扩展性的 2D 组件化战斗底层

一个专为 **2D 动作、清版及 ARPG** 打造的组件化战斗系统。

## 🧠 核心设计理念

系统将复杂的战斗过程拆分为三个绝对隔离的维度：

| 模块 | 职责 | 说明 |
| :--- | :--- | :--- |
| **属性组件** | 战斗数据的唯一来源 | 攻击盒、受击盒、UI 均从这里读写，管理基础值与修改器。 |
| **伤害计算器** | 唯一的伤害公式所在地 | 静态类统一处理，外部脚本**绝对禁止**自行计算伤害。 |
| **碰撞盒 (Hit/Hurt)** | 仅负责物理区域检测 | 不含任何伤害逻辑，动画、特效、击退全交由外部表现层处理。 |

## 📦 安装与快速上手

### 1. 启用插件
将 `addons/combat_system/` 复制到工程目录。在 `项目 -> 项目设置 -> 插件` 中勾选 **「战斗系统」**。

### 2. 最小可运行结构
在任何角色（玩家或敌人）节点下，挂载以下同级节点：

**角色 (Node2D / CharacterBody2D)**
- 属性组件 (StatsComponent) 👈 **必须，战斗数据核心**
- 攻击盒 (AttackHitbox: Area2D) 👈 *可选，攻击方才有*
  - CollisionShape2D
- 受击盒 (Hurtbox: Area2D) 👈 *可选，能被攻击才有*
  - CollisionShape2D

> **⚠️ 注意：**
> 攻击盒 / 受击盒 **必须** 与属性组件同父同级。找不到属性组件时，盒子会自动报错并安全禁用（不会导致项目崩溃）。

### 3. 动画驱动判定
打开 `AnimationPlayer`，为攻击动画添加**属性轨道 (Property Track)**，选中 `AttackHitbox`，勾选 `启用`。
在武器挥出的瞬间设为 `true`，收招时设为 `false`。动画怎么播，判定就怎么走。

## 🧮 核心数值与伤害计算公式

本系统采用行业成熟的乘区与减法混合公式，确保数值成长平滑且不会出现数值崩坏。

### 1. 属性叠加公式
所有的动态效果（Buff、装备）都作为**修改器**附加在基础值上。

```text
最终属性 = (基础值 + 固定值总和) × (1 + 百分比加算总和) × 百分比乘算总值
```

*注：`最大生命值` 在计算完上述结果后，还会再乘一次 `(1 + 最大生命百分比)`。*

### 2. 命中判定
命中率与闪避率直接进行减法对抗，被钳制在 0% 到 100% 之间。

```text
实际命中率 = Clamp(攻击方命中率 - 防守方闪避率, 0.0, 1.0)
```

### 3. 基础伤害与加成
优先计算基础攻击与倍率，再叠加所有增伤乘区（加法叠加，防止数值爆炸）。

```text
基础伤害 = (攻击属性值 + 招式固定加值) × 招式倍率
总增伤 = 通用伤害加成 + 物理/法术类别加成 + 情境加成
情境加成 = 对盾增伤 + 低血增伤 + 满血增伤 (根据触发条件叠加)
最终伤害 = 基础伤害 × (1.0 + 总增伤)
```

### 4. 暴击判定
同样的减法对抗，暴击后乘上总暴击倍率。

```text
实际暴击率 = Max(0, 攻击方暴击率 - 防守方暴击抗性)
若暴击触发：当前伤害 = 当前伤害 × (暴击倍率 + 暴击伤害加成)
```

### 5. 防御减免（递增递减公式）
防御力采用 `防/(防+100)` 的经典递减公式。100 点防御对应 50% 减伤，永远无法达到 100% 免伤。

```text
// 先计算穿透后的有效防御
有效防御 = Max(0, 防守方防御值 × (1 - 攻击方穿透率) - 攻击方穿透值)
减免率 = 有效防御 / (有效防御 + 100.0)
当前伤害 = 当前伤害 × (1.0 - 减免率)
```

### 6. 格挡与最终减伤
最后结算格挡和全局减伤，这两项都是纯粹的乘法减免。

```text
若触发格挡：当前伤害 = 当前伤害 × (1.0 - 格挡减伤)
最终伤害 = 当前伤害 × (1.0 - 最终减伤)
```

### 7. 生存与反伤结算（受击盒）
伤害并非瞬间扣除，而是先由护盾吸收。

```text
护盾吸收 = Min(当前护盾值, 最终伤害)
溢出伤害 = 最终伤害 - 护盾吸收
真实扣血 = 溢出伤害
```

**反伤计算**：防守方受到伤害后，根据自身的 `反伤比例`，直接将等量真实伤害传递给攻击方（绕过攻击方的受击盒，无视无敌）。

```text
反伤值 = 最终伤害 × 防守方反伤比例
```

## 🛠️ 模块详细解析

### 1. 属性模板 (Stat Block) - 角色的基础数值配置
策划填写的配置表，用不到的直接默认。支持中文字段名，新建方式：`右键 -> 新建资源 -> 搜索「属性模板」`。

*   **生命/护盾/法力**：包含最大生命、回复、护盾强度、法力消耗等。
*   **进攻**：物理/法术攻击、穿透、暴击率、暴击倍率、攻击速度、攻击范围。
*   **防御**：物理/法术防御、闪避率、格挡减伤、最终减伤（递减公式：`防/(防+100)`）、韧性。
*   **移动**：移速、加速/减速度、跳跃、冲刺。
*   **受击**：无敌时间、霸体阈值、击退抗性、反伤比例。

### 2. 属性组件 (Stats Component) - 数据与修改器的容器
状态字段：`当前生命值` / `当前护盾值` / `当前法力值`。

**核心 API**：
*   `获取属性(名)`：拿最终值（基础 + 修改器）。
*   `应用伤害(值)`：先扣盾后扣血，血量归零发送 `死亡` 信号。
*   `添加修改器()` / `移除来源()`：管理 Buff 与装备数值。
*   `获取快照()`：返回当前状态字典，供 UI 层使用。

**修改器叠加方式**：
*   **固定值**：直接加减（+10攻击）。
*   **百分比加算**：先加再乘（+10% 与 +20% = +30%）。
*   **百分比乘算**：独立乘区（×1.1 与 ×1.2 = ×1.32）。

**高级设置：出生状态**
检查器里可配置「初始生命/护盾/法力百分比」。填 `0.3`，怪物出生就是残血，适合制作濒死 NPC 或精英怪。

### 3. 伤害数据与计算流程 (Damage Data & Calculator)
`伤害数据 (Damage Data)` 是对一次招式的描述（资源文件）。包含：招式倍率、固定加值、击退力度、无视护盾、可暴击等属性。详细公式见上方 **核心数值与伤害计算公式**。

### 4. 受击反馈与表现 (Hit Feedback)
*   **受击盒 (Hurtbox)**：自动扣血并发送信号（`受到伤害`、`被闪避`、`格挡成功`、`反伤触发`）。
*   **受击反馈设置 (Hit Feedback Resource)**：拖入属性组件槽位即可一键生效：
	*   **闪白**：自动寻找 Sprite2D 材质瞬间变白。
	*   **顿帧**：短暂降低 `Engine.time_scale`（内置 `ignore_time_scale` 防卡死）。
	*   **击退**：给同级 `CharacterBody2D` 施加物理速度。
	*   **飘字**：纯代码生成 Label，自动向上飘出销毁。

### 5. 数值条 UI (UI Stats Bar & 2D 数值条)
系统提供了两套 API 一致的数值条：`数值条 (Node2D)` 用于怪物头顶，`UI属性条 (Control)` 用于游戏 HUD。

*   **跨场景绑定**：UI属性条支持手动拖拽、按分组查找（如自动找“玩家”组）、代码绑定，完美解决玩家与 UI 不在同一场景的问题。
*   **多材质渲染**：支持纯色绘制与纹理绘制。纹理可自由染色、裁剪（适合异形血条）或拉伸。
*   **动态特效**：自带平滑缓动；支持掉血粒子喷发（可自定义粒子形状、纹理、重力与大小）。

### 6. 状态管理系统 (Status Component) - Buff 与 Debuff
同级需有 `属性组件`。基于 `状态模板 (Status Data)` 新建资源。
定义修改哪个属性、加多少值、持续时长与最大层数。
自动管理层数叠加，到期自动调用 `移除来源` 清理属性，并发出 `状态更新` 与 `状态结束` 信号。

## ⚠️ 常见坑与避雷指南

> **请务必核对以下常见错误：**
> 1. **找不到属性组件**：属性组件必须和攻击盒/受击盒同父同级。
> 2. **属性名写错**：名字写错会静默返回 0，**不报错**。请严格核对中文命名。
> 3. **变量名撞车**：不要在脚本里写 `@export var 阵营: 阵营.类型`，换个变量名。
> 4. **顿帧卡死**：如果你自己做受击计时器，必须设置 `ignore_time_scale = true`。

## 🚀 扩展与进阶指南

### 添加新属性 / 新状态
*   **加新属性**：在 `stat_block.gd` 里加一行 `@export var 新属性名: float = 0.0` 即可。
*   **加新状态**：新建一个 `状态模板` 的 `.tres` 文件，配置好改哪个属性、加多少。

### 架构设计原则 (Design Principles)
1. 信号只发事件，不发全量数据（用 `获取快照()`）。
2. 数值只在属性组件里，公式只在计算器里。
3. 攻击盒/受击盒只负责检测与反馈，动画/移动逻辑全权交由角色脚本。
4. 命名不轻易改，改就全项目替换。

### 开发者工具
*   **调试面板**：按 `F2` 呼出，按离玩家距离排序扫描场景所有属性组件。可直接拖动滑动条实时修改基础数值，无需重启游戏。
*   **自动化测试**：新建空场景挂载 `测试场.gd`，`F5` 运行。控制台自动跑完 15 项伤害公式测试，全绿说明底层健康。
