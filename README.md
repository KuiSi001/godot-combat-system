================================================================
  一、三分钟上手
================================================================

【目录结构】
  addons/combat_system/
	plugin.cfg
	plugin.gd
	README.txt
	icons/
	core/
	  stat_block.gd          属性模板（Resource）
	  damage_data.gd         伤害数据（Resource）
	  damage_calculator.gd   伤害计算器（静态类）
	  faction.gd             阵营关系（静态类）
	  debug_badge.gd         调试徽章（静态工具）
	  hit_feedback.gd        受击反馈设置（Resource）
	  status_data.gd         状态模板（Resource）
	nodes/
	  stats_component.gd     属性组件（Node）
	  attack_hitbox.gd       攻击盒（Area2D）
	  hurtbox.gd             受击盒（Area2D）
	  数值条.gd              数值条（Node2D）
	  status_component.gd    状态组件（Node）
	debug/
	  combat_debug_panel.gd  调试面板（Window）
	测试/
	  测试场.gd              自动化测试脚本

【启用插件】
  项目 → 项目设置 → 插件 → 勾选「战斗系统」

【最小可运行结构】
  每个角色（玩家或敌人）都挂这么一份：

	角色 (Node2D / CharacterBody2D)
	  ├── 属性组件         ← 必须，同级
	  ├── 攻击盒 (Area2D)  ← 可选，攻击方才有
	  │     └── CollisionShape2D
	  └── 受击盒 (Area2D)  ← 可选，能被攻击才有
			└── CollisionShape2D

  规则：攻击盒 / 受击盒和属性组件必须同父同级。找不到属性组件时，
		盒子会报错并自我禁用（不会崩）。


================================================================
  二、核心概念
================================================================

  属性组件      战斗数据的唯一来源。攻击盒 / 受击盒 / UI 都从这里读写
  属性模板      属性的基础值配置。策划填，多个角色可共用一份 .tres
  修改器        运行时叠加的 Buff / 装备数值。基础值 + 修改器 = 最终值
  伤害数据      一次招式的描述（用哪个属性、倍率多少），不是数值本身
  伤害计算器    唯一的伤害公式所在地。外部不准算伤害
  攻击盒 / 受击盒   只负责检测。动画、特效、击退全交给角色脚本或受击反馈


================================================================
  三、属性模板 (stat_block.gd)
================================================================

角色的基础数值。字段很多，用不到的直接保持默认值。

【生命】最大生命值 / 生命回复 / 生命偷取 / 生命偷取效率 / 最大生命百分比
【护盾】最大护盾值 / 护盾回复 / 护盾回复延迟 / 护盾强度
【法力】最大法力值 / 法力回复
【进攻-通用】伤害加成 / 命中率 / 暴击率 / 暴击倍率 / 暴击伤害加成 / 攻击速度 / 攻击范围
【进攻-物理】物理攻击 / 物理穿透 / 物理穿透率 / 物理伤害加成
【进攻-法术】法术攻击 / 法术穿透 / 法术穿透率 / 法术伤害加成 / 冷却缩减
【进攻-特殊】对盾伤害加成 / 低血增伤 / 低血阈值 / 满血增伤
【防御-基础】物理防御 / 法术防御 / 最终减伤（递减公式：防 / (防 + 100)）
【防御-进阶】闪避率 / 格挡率 / 格挡减伤 / 暴击抗性 / 韧性
【移动】移动速度 / 加速度 / 减速度 / 跳跃力 / 跳跃次数 / 冲刺次数
【受击】受击无敌时间 / 霸体阈值 / 击退抗性 / 受击硬直抗性 / 反伤比例

新建方式：文件系统右键 → 新建资源 → 搜「属性模板」


================================================================
  四、属性组件 (stats_component.gd)
================================================================

战斗数据唯一来源。
状态字段：当前生命值 / 当前护盾值 / 当前法力值

【核心方法】
  获取属性(名)                   拿最终值（基础 + 修改器）
  添加修改器(名, 数值, 类型, 来源)  加 Buff / 装备
  移除来源(来源)                 批量移除某来源的所有修改器
  应用伤害(值)                   先扣盾后扣血，血归零发「死亡」
  治疗(值) / 回蓝(值) / 消耗法力(值)
  重置状态()                     拉满血 / 盾 / 蓝
  进入无敌(时长) / 清除无敌() / 是否无敌中()
  获取快照()                     返回状态完整字典（供 UI 用）

【修改器三种叠加方式】
  固定值        直接加              +10 攻击
  百分比加算    所有百分比先加再乘   +10% 与 +20% = +30%
  百分比乘算    各自独立乘          ×1.1 与 ×1.2 = ×1.32


================================================================
  五、伤害数据 (damage_data.gd)
================================================================

一次招式的描述。默认值不配也能跑（物理攻击 × 1.0）。
【招式描述】伤害类别 / 攻击属性名 / 招式倍率 / 固定加值
【附加】击退力度 / 击退方向 / 无视护盾 / 可暴击
【运行结果】最终伤害 / 是否暴击 / 是否命中 / 是否格挡


================================================================
  六、伤害计算流程
================================================================

  1. 命中判定：命中率 - 闪避率
  2. 取攻防：按类别取攻击属性 + 防御 + 类别加成 + 穿透
  3. 基础伤害：(攻击值 + 固定加值) × 招式倍率
  4. 加成：× (1 + 通用加成 + 类别加成 + 情境加成)
  5. 暴击判定：暴击率 - 暴击抗性
  6. 防御减免：有效防御 = max(0, 防御 × (1 - 穿透率) - 穿透值)
  7. 格挡判定：伤害 × (1 - 格挡减伤)
  8. 最终减伤：伤害 × (1 - 最终减伤)


================================================================
  七、攻击盒 (attack_hitbox.gd)
================================================================

攻击判定区。由动画控制开关。
【字段】所属阵营 / 招式 / 启用 / 显示调试徽章
【关键行为】启用从 false → true 瞬间：清空命中表 + 延迟一帧主动扫描。

动画控制：用属性轨道（Property Track）直接改 `启用`。
多段攻击：动画里开开关关多次即可。


================================================================
  八、受击盒与受击反馈 (hurtbox.gd & hit_feedback.gd)
================================================================

受击判定区。收到伤害后自动扣血、发信号并触发表现反馈。

【表现反馈设置 (hit_feedback.gd)】
  这是一个 Resource，可以拖入 `属性组件` 的「受击反馈」槽位。
  如果配置了，受击时会自动触发：
  1. 闪白：自动寻找同级 Sprite2D，瞬间变白再淡出。
  2. 顿帧：短暂降低 Engine.time_scale（需用 ignore_time_scale 计时）。
  3. 击退：根据招式击退力度，给同级 CharacterBody2D 施加 velocity。
  4. 飘字：纯代码生成 Label，向上飘出伤害数字并自动销毁。

【受击盒信号】
  受到伤害(伤害) / 被闪避(伤害) / 格挡成功(伤害) / 反伤触发(数值, 目标)


================================================================
  九、数值条（血条/盾条） (数值条.gd)
================================================================

挂在怪物头顶，自动绑定同级 `属性组件`。
支持纯色绘制、纹理绘制，带平滑缓动与掉血粒子特效。

【字段说明】
  目标数值          生命 / 护盾 / 法力
  跟随纹理尺寸      勾选后，宽高自动跟随拖入的纹理大小
  使用纹理          切换到纹理绘制模式
  填充方式          拉伸（适合纯色渐变）/ 裁剪（适合花纹异形）
  动画模式          瞬间 / 平滑 / 粒子
  粒子参数          重力、阻力、初速度、大小、存活时间均可调

【调试开关】
  勾选「显示调试徽章」并打开编辑器调试菜单，可看到实时状态。
  受击盒：蓝圈(常态) / 青圈(无敌) / 红圈(命中) / 蓝圈(闪避)


================================================================
  十、状态管理系统 (status_component.gd & status_data.gd)
================================================================

用于挂载 Buff / Debuff 状态。

【状态模板 (status_data.gd)】
  新建 Resource 资源，定义：状态名、持续时长、最大层数、修改属性名、
  修改数值、修改类型、图标。

【状态组件 (status_component.gd)】
  挂在怪物上，同级需有 `属性组件`。
  方法：添加状态(模板) / 移除状态(名) / 清空所有状态()
  信号：状态更新(名, 层数, 剩余时间) / 状态结束(名)
  机制：自动管理层数叠加，到期自动 `移除来源` 清理属性。


================================================================
  十一、调试面板与自动测试
================================================================

【调试面板 (combat_debug_panel.gd)】
  挂载在 Window 节点上，按 F2 呼出。
  功能：扫描场景所有属性组件，按离玩家距离排序。
		点击目标，可直接拖动滑动条实时修改其所有基础数值。

【自动测试 (测试场.gd)】
  新建空场景 → 挂载此脚本 → F6 运行。
  会在控制台自动跑完 15 项伤害公式测试，全绿说明插件工作正常。


================================================================
  十二、常见坑
================================================================

1. 找不到属性组件：属性组件必须和攻击盒/受击盒同父同级。
2. 属性名写错：名字写错静默返回 0，不报错。请严格核对名字。
3. 第二次攻击打不中：插件已在 setter 里主动扫描解决。
4. 变量名撞车：不要写 `@export var 阵营: 阵营.类型`，换个名字。
5. 顿帧卡死：计时器必须用 `ignore_time_scale = true`。


================================================================
  十三、属性命名约定
================================================================

属性名必须和 `属性模板` 字段名完全一致（支持中文）。
当前合法属性名清单见「三、属性模板」。


================================================================
  十四、扩展指南与设计原则
================================================================

【设计原则】
1. 信号只发事件，不发全量数据（用获取快照()）。
2. 数值只在属性组件里，公式只在计算器里。
3. 攻击盒/受击盒只负责检测与反馈，动画/移动逻辑交给角色脚本。
4. 命名不轻易改，改就全项目替换。

【加新属性】
在 stat_block.gd 加 `@export var 新属性名: float = 0.0` 即可。

【加新状态】
新建一个 `状态模板` 的 .tres 文件，配置好改哪个属性、加多少。
